Get started

Up and running in minutes

You only need Docker. Migrations run automatically on boot.

bash
# 1. clone
git clone https://github.com/abdelghafourlahrache/betal-lp.git
cd dq-ai-labs

# 2. configure secrets (encryption key + LLM — see below)
cp .env.example .env

# 3. launch everything
docker compose up

Then open localhost:3000 → pick a handle → start the first lab.

bash
# datastores only
docker compose up -d app-db redis demo-db

# backend
cd backend && python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # point DATABASE_URL at localhost:5433
alembic upgrade head && uvicorn app.main:app --reload

# frontend (new terminal)
cd frontend && npm install && npm run dev
AI setup

One of these is all you need

The AI tutor, check-suggestions and failure-explanations work with either a cloud key or a fully local model. Pick whatever fits.

🦙 Ollama FREE · LOCAL

  • No API key, no cloud, no cost
  • Your data never leaves the machine
  • Great for air-gapped / privacy-sensitive teams
bash
# install from ollama.com, then:
ollama pull llama3.1

# in .env (auto-detected if no API key):
OLLAMA_MODEL=llama3.1

🔑 Claude API key BEST QUALITY

  • Highest-quality suggestions & explanations
  • Structured outputs + adaptive reasoning
  • Zero local compute
.env
# get a key at console.anthropic.com
ANTHROPIC_API_KEY=sk-ant-...
AI_MODEL=claude-opus-4-8
Community

Contribute a lab or a stack

Content is just files — no app code required. Drop a YAML in, open a PR. The platform picks it up automatically.

1

Add a file

Create a YAML in backend/labs/ (a lesson) or backend/stacks/ (a tool recipe).

2

Define it

Labs have concept/exercise/challenge steps with server-side graders. Stacks have prose + copyable code + use cases.

3

Open a PR

It validates on load and shows up in the catalog. Maintainers can also author live in the Admin UI.

backend/labs/my-lab.yaml
id: my-lab
title: My Lab
track: Fundamentals
difficulty: beginner
summary: One-line pitch.
dataset: { schema: public, table: customers }
steps:
  - id: do-it
    type: exercise
    title: Build a check
    xp: 20
    builder: { mode: check, table: customers, hint_column: email }
    grader:
      type: check_failing_count
      require_kind: not_null
      require_column: email
      expect: 1
